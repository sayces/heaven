Разделите приложение на независимые слои, чтобы код легко читался и тестировался:
1. Слой маршрутизации (Routes / Controllers) — принимает HTTP-запросы (Express, Fastify, NestJS), проверяет входные данные (валидация с помощью Zod или Joi) и передает их дальше.
2. Слой бизнес-логики (Services) — сердце вашего блога. Здесь описываются правила: как создается статья, кто имеет право ее редактировать, как генерируется slug для ссылки.
3. Слой работы с данными (Repositories / Models) — абстракция над базой данных. Взаимодействует с БД через ORM (например, Prisma, Mongoose или Sequelize). Ближайшие слои не должны знать, какая именно БД используется.


src/
  ├── config/             # Конфигурация (переменные окружения, подключение к БД)
  ├── controllers/        # Обработка запросов (PostController, AuthController)
  ├── middlewares/        # Промежуточное ПО (проверка авторизации, логирование)
  ├── models/ или prisma/  # Схема базы данных
  ├── repositories/       # Прямые запросы к БД (PostRepository)
  ├── services/           # Бизнес-логика (PostService, UserService)
  ├── routes/             # Объявление путей (API Endpoints или SSR роуты)
  └── app.js              # Точка входа в приложение
