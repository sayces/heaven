# Архитектура

JSON API на Express 5 (ESM + TypeScript). Слои: **Router → Controller → Model**.
Это упрощённый MVC: отдельного View нет, его роль выполняет JSON-ответ
контроллера (`res.json(...)`).

## Поток запроса

`src/app.ts` → `src/router` → `src/controllers` → `src/models`

| Слой | Где | Ответственность |
| --- | --- | --- |
| Вход | `src/app.ts` | `express.json()`, `/ping`, монтаж роутера на `/api`, порт `5000` |
| Маршрутизация | `src/router/` | Пути и привязка к контроллерам; `validateId` проверяет `:id` |
| Контроллер | `src/controllers/` | Валидация входа, вызов модели, HTTP-статус и JSON |
| Модель | `src/models/` | Данные и правила: уникальность имени, id, CRUD |

## Структура

```text
src/
├── app.ts
├── router/
│   ├── index.ts           # корневой роутер, монтируется на /api
│   └── user.router.ts     # /users
├── controllers/
│   ├── index.ts           # реэкспорт UserController
│   ├── user/
│   │   └── user.controller.ts
│   └── utils/errorSender.ts
├── middlewares/
│   └── user/validateId.ts
└── models/
    ├── index.ts           # реэкспорт UserModel
    ├── docs.md
    └── user/
        ├── types.ts
        ├── user.mock.ts
        └── user.model.ts
```

## Маршруты

| Метод | Путь | Действие |
| --- | --- | --- |
| `GET` | `/ping` | Проверка живости, ответ `pong` |
| `GET` | `/api` | Приветствие API |
| `POST` | `/api/users/create` | Создать пользователя |
| `GET` | `/api/users` | Список пользователей |
| `GET` | `/api/users/:id` | Пользователь по id |
| `PUT` | `/api/users/:id` | Обновить пользователя |
| `DELETE` | `/api/users/:id` | Удалить пользователя |

## Слои, которых нет намеренно

- `services/` — бизнес-правил мало, они живут в модели. Слой понадобится,
  когда одно правило начнут использовать несколько контроллеров (например,
  регистрация и админка) или появятся внешние вызовы.
- `repositories/` — хранилище одно: массив в памяти. Обёртка над ним сейчас
  ничего не абстрагирует. При переходе на БД (Prisma, Mongoose) её стоит
  добавить, чтобы модель не знала о драйвере.
- `config/` — настраивается только порт, он захардкожен. `config/` появится
  вместе с `.env`.
- `views/` — API возвращает JSON, шаблоны не нужны. View — это `res.json()`.

## Соглашения

- Именованные экспорты, без `export default`.
- `controllers/index.ts` и `models/index.ts` — только реэкспорт.
- Ошибки модели не отдаются клиенту как есть: контроллер пропускает их через
  `errorSender` и отвечает `500`.

## Известные ограничения

- Нет персистентности (сохранения): данные в памяти, при перезапуске
  возвращаются стартовые значения из `user.mock.ts`.
- `PUT` и `DELETE` для несуществующего id возвращают `500`, хотя в контроллере
  есть ветка `404`: модель бросает `Error`. Чтобы `404` заработал, модель
  должна возвращать `null`/`false`, а не бросать исключение.
- `GET /api/users` и `GET /api/users/:id` возвращают поле `password`. Для
  учебного мока это допустимо, для реального API поле нужно исключать.
